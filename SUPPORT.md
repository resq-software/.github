# Getting help

Depending on what you need, one of these is usually the right place:

## Documentation

- **User docs**: [docs.resq.software](https://docs.resq.software) — guides, API reference, tutorials.
- **Contributor onboarding**: [CONTRIBUTING.md](./CONTRIBUTING.md) in this repo.
- **Per-repo dev guide**: every `resq-software/<repo>` ships an `AGENTS.md` at its root — the canonical plain-text dev guide for that repo (build commands, architecture notes, standards).

## Usage questions

- [GitHub Discussions](https://github.com/orgs/resq-software/discussions) on the org — best for "how do I…?" and design conversations. Search first; many are already answered.

## Bug reports / feature requests

- Open an issue on the specific repo using the bug report or feature request template.
- If you're unsure which repo, open against [`resq-software/.github`](https://github.com/resq-software/.github/issues) and we'll route.

## Security issues

- **Not** a public issue. See [SECURITY.md](./SECURITY.md) for the private reporting process.

## Response expectations

This is best-effort community support. Maintainers respond when they can. Security reports get faster attention per [SECURITY.md](./SECURITY.md).

Paid support / consulting is not offered at this time.
